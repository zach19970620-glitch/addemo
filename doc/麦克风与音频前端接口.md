# 麦克风与音频前端接口

> 文档版本：1.0
>
> 范围：系统采麦、`audioprocessor.aar` 前端、App 封装与调用点
>
> 最后更新：2026-10-07

## 1. 结论

本仓库没有独立的多麦克风阵列或波束成形接口。音频链路是两层：

1. **系统采麦**：`AudioRecord`，16 kHz、单声道、PCM 16 bit。
2. **可选前端**：`app/libs/audioprocessor.aar`。Java 表面是 mic / ref / out 三缓冲，系统 C 接口是 `FrtEndProc*`。当前 `FrtEndProc` 只做单通道降噪（ANS），参考通道在进入处理前被覆盖，`AECProc` 未被调用。

默认关闭。`features.aec_enabled` 为 `false`。打开后 `VoiceEngine` 仍传入 `refPcm = null`，参考通道由封装填静音。

## 3. 数据流

```text
AudioRecord (VOICE_RECOGNITION, 16 kHz, mono, PCM16)
  → NoiseSuppressor（绑定 audioSessionId，失败不影响采麦）
  → 1280 字节/帧（约 40 ms）
  → aec_enabled == false：原样 writePcm
  → aec_enabled == true：切成 480 字节（240 sample）
       → AudioProcessor.process(mic, ref, out)
       → FrtEndProc：ANS，忽略 ref
       → writePcm(out)
```

路线 A（本地火山密钥）和路线 B（Device API）共用这一段。识别文本之后的上报、轮询不经过该库。

## 4. 系统采麦

类：`com.haokai.addemo.speech.AudioPcmCapture`

```kotlin
fun start(onFrame: (ByteArray) -> Unit): Boolean
fun stop()
```

常量：

| 常量 | 值 |
| --- | --- |
| `SAMPLE_RATE` | 16000 |
| `FRAME_BYTES` | 1280 |
| 声道 | `AudioFormat.CHANNEL_IN_MONO` |
| 编码 | `AudioFormat.ENCODING_PCM_16BIT` |
| 音源 | `MediaRecorder.AudioSource.VOICE_RECOGNITION` |

行为：

- 已在采集时 `start()` 返回 `true`，避免会话就绪回调重复打开麦克风。
- `getMinBufferSize` 无效、构造失败或 `STATE_INITIALIZED` 未就绪时返回 `false`，并释放已创建对象。
- 缓冲区至少为 `max(minBufferSize, FRAME_BYTES * 4)`。
- `NoiseSuppressor.isAvailable()` 为 false，或 `create` / `enabled = true` 失败时只打日志，采集继续。
- `stop()` 依次 `AudioRecord.stop`、释放 `NoiseSuppressor`、`AudioRecord.release`，并 `join` 采集线程最多 500 ms。
- `read` 返回负数时退出循环。

## 5. App 封装

类：`com.haokai.addemo.speech.AecAudioProcessor`

```kotlin
fun init(): Boolean
fun isReady(): Boolean
fun process(micPcm: ByteArray, refPcm: ByteArray?, onClean: (ByteArray) -> Unit)
fun release()
```

常量：`SEG_SAMPLES = 240`，`SEG_BYTES = 480`。

行为：

- `init()` 调用 `AudioProcessor.getInstance().init()`。异常时返回 `false`，后续 `process` 原样回调麦数据。
- `process` 把麦数据（以及非空的 ref）攒到 480 字节再送入库。不足一段的字节留到下一次。
- `refPcm == null` 或 ref 不足 480 字节时，该段 ref 填 0。
- `AudioProcessor.process` 抛错时，该段改为回传原始 mic。
- 一次 `process` 可能多次调用 `onClean`。输出是 `outSeg.copyOf()`，避免下一段覆盖。
- `release()` 调用 `AudioProcessor.getInstance().release()` 并清空缓存。未 init 时直接返回。

## 6. 算法库 Java 接口

类：`com.algorithm.audio.AudioProcessor`  
加载：`System.loadLibrary("native")`  
实例：`getInstance()` 为同步懒汉单例。

```java
public final class AudioProcessor {
    public static AudioProcessor getInstance();

    public void init();
    public void release();

    /** 每段 240 个 short，即 480 字节 PCM16。 */
    public void process(short[] mic, short[] ref, short[] out);

    /** 每段 480 字节。指针按 int16 解释，与 short[] 重载进入同一个 FrtEndProc。 */
    public void process(byte[] mic, byte[] ref, byte[] out);

    private native void native_init();
    private native void native_release();
    private native void native_process(short[] mic, short[] ref, short[] out);
    private native void native_process(byte[] mic, byte[] ref, byte[] out);
}
```

厂商示例 `TestActivity` 用 raw `mic` / `ref`，按 240 采样读写，输出 `/sdcard/aes.pcm`：

```java
audioProcessor.init();
final int SEG_LEN = 240;
byte[] bufMic = new byte[SEG_LEN << 1];
byte[] bufRef = new byte[SEG_LEN << 1];
byte[] bufOut = new byte[SEG_LEN << 1];
audioProcessor.process(bufMic, bufRef, bufOut);
```

示例工程依赖：`doc/AudioProcessor/app/build.gradle` 的 `implementation files('libs/audioprocessor.aar')`。

## 7. 系统 C 接口

`libnative.so` 导出：

```text
Java_com_algorithm_audio_AudioProcessor_native_1init
Java_com_algorithm_audio_AudioProcessor_native_1release
Java_com_algorithm_audio_AudioProcessor_native_1process___3S_3S_3S
Java_com_algorithm_audio_AudioProcessor_native_1process___3B_3B_3B
```

JNI 行为：

- `native_init`：若尚未初始化，调用 `FrtEndProcInit()`，并置内部 flag。
- `native_release`：若已初始化，调用 `FrtEndProcFini()`，并清 flag。
- `native_process`：flag 未置位则直接返回。否则 `GetShortArrayElements` 或 `GetByteArrayElements` 取三块缓冲，调用 `FrtEndProc(mic, ref, out)`，再以 mode `0`（拷回并释放）`Release*ArrayElements`。未初始化时三个数组都不会被写入。

`libaudio_processor.so` 与本链路相关的导出：

```c
void FrtEndProcInit(void);
void FrtEndProc(short *mic, short *ref, short *out);
void FrtEndProcFini(void);

void AEC_Init(void);
void AECProc(...);
void AEC_Fnit(void);

void ANSInit(void);
void ANS(...);
void ANSFnit(void);
void ANSParaInit(void);
void ANSgParaInit(void);
```

`FrtEndProcInit` 顺序：

1. 按 **1 路** 分配时域缓冲，长度 **481**（`ckd_calloc_2d(1, 481, 4)`）。
2. 分配频域缓冲：1 × 256 × 8 字节一类，以及 1 × 256 × 4 字节一类（512 点 FFT，256 个频点）。
3. `SigFFTInit()` → `Matrix_math_Init()` → `AEC_Init()` → `ANSInit()` → `ANSgParaInit()`。

`FrtEndProc` 实际路径：

```text
SigBufFill(mic, buf, 1, 1)
  → FFTAnalysis
  → ANS
  → FFTSynthesis
  → SigExp(..., out, ...)
  → SigBufShift
```

反汇编里，进入 `SigBufFill` 之前第二个参数寄存器被换成内部缓冲指针。因此 **`ref` 不参与本帧处理**。`AEC_Init` 会在 init 时执行，`AECProc` 不在 `FrtEndProc` 调用图中。

`FrtEndProcFini` 释放上述二维 / 三维缓冲，然后 `Matrix_math_Fnit`、`AEC_Fnit`、`ANSFnit`、`ANSgParaFini`。

## 8. VoiceEngine 调用

`VoiceEngine` 持有：

```kotlin
private val capture = AudioPcmCapture()
private val aec = AecAudioProcessor()
private var useAec = false
```

打开条件（路线 A `startLocalSession`、路线 B `startServerTurn` 相同）：

```kotlin
useAec = configRepository.load().features.aec_enabled && aec.init()
```

会话就绪后，在 `voice-mic` 线程：

```kotlin
capture.start { pcm ->
    if (useAec) {
        aec.process(pcm, refPcm = null) { clean ->
            client?.writePcm(clean)
        }
    } else {
        client?.writePcm(pcm)
    }
}
```

`capture.start` 返回 false 时，状态设为「无法打开麦克风」，且不再自动重开。

释放 `aec` 的位置：

| 位置 | 时机 |
| --- | --- |
| `startServerTurn` 的 catch | 准备凭证 / 建任务失败 |
| `beginSubmit` | 开始上报最终文本，先 `capture.stop()` |
| `stopSession` | 停会话 |
| `VoiceEngine.release` | 引擎销毁，在 `stopSession` 之后再调一次 |

`KioskScreen` 调试行显示 `aec=${voiceDebug.aecEnabled}`，只反映本次 `init()` 是否成功，不表示参考信号有效。


```kotlin

```

开启方式：把 `aec_enabled` 设为 `true` 后重新安装。`init()` 失败时自动退回原始 PCM，识别链路仍可用。

## 10. 使用约束

- 算法库按 **240 个 int16 采样** 处理一帧。App 侧 1280 字节采集帧会被切成两段 480 字节，余 320 字节留在 `AecAudioProcessor` 缓存里，与下一帧拼接。
- 库内状态是进程级单例。`init` / `release` 必须成对，且不要并发 `process`。当前只在 `voice-mic` 单线程里 `process`。
- 名称是 AEC，现有 `FrtEndProc` 实现是单通道 ANS。没有播放参考信号时，打开该开关不会做回声消除。
- 系统 `NoiseSuppressor` 与库内 ANS 相互独立。`aec_enabled == false` 时仍可能启用 `NoiseSuppressor`。
- 板子目标为 RK3588 `arm64-v8a`。AAR 另带 `armeabi-v7a` 与 `x86_64`，本 Demo 不使用这两套 ABI。
